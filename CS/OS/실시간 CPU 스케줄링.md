# 실시간 CPU 스케줄링
## 실시간 시스템
**실시간 시스템**이란 작업 완료까지의 시간 제약(Deadline)이 매우 중요한 시스템이다.

**실시간 시스템 특성**
- **결정론적 동작: 예측 가능한 응답 시간
- 시간 제약: 데드라인 준수 필수
- 우선순위 기반: 중요한 태스크 우선 처리
- 저지연: 빠른 응답 시간

**실시간 시스템 분류**
- **경성 실시간 시스템**(Hard Real-Time System): 마감시간을 놓치면 치명적인 오류가 발생한다. (미사일 제어, 자동차 에어백)
- **연성 실시간 시스템**(Soft Real-Time System): 마감시간을 놓치면 성능 저하가 발생한다. (동영상 스트리밍, 온라인 게임)

## 작업 모델
실시간 스케줄링에서는 작업이 마감 시간 내에 완료 가능한지 판단하기 위해 작업을 모델링한다.

**주기적 작업**(Periodic Task)​은 일정한 간격으로 CPU를 필요로 하는 작업으로 다음과 같은 요소로 표현할 수 있다.

**주기**(p): 작업이 반복되는 간격
**실행 시간**(t): 한 번 실행에 필요한 CPU 시간
**마감 시간**(d): 작업이 완료되어야 하는 시간

경성 실시간 시스템은 이러한 정보를 기반으로 작업이 마감 시간 내에 완료될 수 있는지 판단하고, 가능한 경우에만 작업을 실행한다.

## 스케줄링 알고리즘
경성 실시간 시스템의 경우, 모든 작업의 시간 제약을 만족해야 하므로 특수한 스케줄링 기법이 필요하다.

### RM(Rate-Monotonic)
정적 우선순위 방식으로 주기가 짧을수록 높은 우선순위를 부여하는 스케줄링 방식이다.

각 작업의 `{실행 시간}/{주기}`의 비율을 더한 총 CPU 이용률(`U`)이 다음 상한선 이하일 때 마감 시간이 보장된다.
`U = Σ(t/p) ≤ n(2^(1/n) - 1)` (n → ∞ 일 때: `U ≤ ln(2) ≈ 0.693`)

#### 예시
다음과 같은 두 프로세스가 있다고 하자.
| | P1 | P2 |
|---|---|---|
| **주기** | p1 = 50 | p2 = 100 |
| **실행 시간** | t1 = 20 | t2 = 35 |

CPU 이용률의 합은 `20/50 + 35/100 = 0.4 + 0.35 = 0.75`<br>
2개의 태스크가 있을때 CPU 이용률의 상한값은 `2(2^(1/2) - 1) ≈ 0.828`<br>
`0.75 ≤ 0.828`로 조건을 충족하므로 스케줄링이 가능하다.

주기가 더 짧은 P1에게 높은 우선순위를 부여한다.
P1이 먼저 실행되고, P1이 작업을 완료한 후에 P2가 시작한다.
P1의 다음 주기가 시작되는 50시점에서 P2는 P1에 의해 선점된다.
이후 P1은 두 번째 기간의 작업을 완료하고, P2는 남은 작업을 완료할 수 있다.

## EDF(Earliest-Deadline-First)
동적 우선순위 방식으로 마감 시간이 가장 가까운 작업을 우선 실행하는 스케줄링 방식이다.

CPU 이용률이 1 이하일 때 마감 시간이 보장된다. (컨텍스트 스위칭 비용 제외)
`U = Σ(t/p) ≤ 1`

그러나 과부하(U > 1)로 인해 하나의 작업이 마감 시간을 놓치면, 이후 작업들이 연쇄적으로 마감 시간을 놓치게 되는 **도미노 현상**(Domino effect)이 발생할 수 있다.

#### 예시
다음과 같은 두 프로세스가 있다고 하자.
| | P1 | P2 |
|---|---|---|
| **주기** | p1 = 50 | p2 = 80 |
| **실행 시간** | t1 = 25 | t2 = 35 |
