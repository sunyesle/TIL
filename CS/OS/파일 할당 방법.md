# 파일 할당 방법
파일 할당 방법은 파일의 데이터를 디스크의 블록에 어떻게 배치할 것인지 결정하는 방법이다.

## 연속 할당(Contiguous Allocation)
파일의 모든 블록을 디스크 상의 연속된 물리적 블록에 저장한다.

파일의 시작 블록과 크기를 알고 있으면 각 블록의 위치를 쉽게 계산할 수 있어 순차 접근과 직접 접근이 모두 빠르다.

파일의 생성과 삭제가 반복되면 가용 공간이 여러 곳으로 나뉘어 외부 단편화가 발생할 수 있다.

파일 크기 변경이 어렵다. 파일 크기가 증가 할 때 뒤쪽의 연속된 공간이 이미 사용 중이라면, 파일을 더 큰 연속 공간이 있는 다른 위치로 ​통째로 이동해야 할 수 있다.

## 연결 할당(Linked Allocation)
파일의 블록을 디스크의 여러 위치에 저장하고, 각 블록에 다음 블록의 위치를 가리키는 포인터를 저장하여 연결한다.

파일의 블록이 연속된 공간에 있을 필요가 없기 때문에 외부 단편화가 발생하지 않으며, 파일 크기 변경이 쉽다.

각 블록에 다음 블록의 위치를 저장하기 위한 추가 공간이 필요하다.

직접 접근을 위해서는 포인터를 순차적으로 따라가야 하므로 비효율적이며, 순차 접근에 적합하다.

블록에 저장된 포인터가 손상되거나 유실되면 이후 블록에 접근하지 못할 수 있어 신뢰성 문제가 발생할 수 있다.

<img width="420" height="435" alt="12_06_LinkedAllocation" src="https://github.com/user-attachments/assets/14ca2180-6b95-41d9-93d4-287bf951bbd2" />

MS-DOS에서 사용된 **FAT**(File Allocation Table)​은 연결 할당의 변형으로, 각 블록의 연결 정보를 별도의 테이블에 저장한다. FAT를 메모리에 캐시하면 직접 접근 성능을 향상시킬 수 있다. ([관련 글](https://velog.io/@inmo/FAT%ED%8C%8C%EC%9D%BC%EC%8B%9C%EC%8A%A4%ED%85%9C-FAT-%EC%98%81%EC%97%AD))

## 색인 할당(Indexed Allocation)
파일의 데이터 블록 위치를 하나의 색인 블록(Index Block)에 모아서 관리​한다.

데이터 블록이 디스크의 여러 위치에 분산되어 있어도 색인 정보를 이용해 원하는 데이터 블록에 직접 접근할 수 있다.

파일의 블록이 연속된 공간에 있을 필요가 없기 때문에 외부 단편화가 발생하지 않으며, 파일 크기 변경이 쉽다.

각 파일마다 색인 블록을 저장하기 위한 추가 공간이 필요하며, 작은 파일에서도 하나의 색인 블록을 할당해야 하므로 공간이 낭비될 수 있다.

<img width="543" height="480" alt="12_08_IndexedAllocation" src="https://github.com/user-attachments/assets/8542dd2e-853f-4905-b945-29f8f2450080" />

색인 블록의 크기보다 큰 파일을 관리하기 위해 여러 단계의 색인을 사용할 수도 있다. 대표적으로 연결 색인 방식, 다단계 색인 방식, 결합 방식 등이 있다. Unix의 inode는 직접 블록 포인터와 단일·이중·삼중 간접 포인터를 조합하는 ​결합 방식을 사용한다.
