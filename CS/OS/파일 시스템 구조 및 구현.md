# 파일 시스템 구조 및 구현

## 파일 시스템 계층 구조

| 계층 | 주요 기능 |
|---|---|
| **응용 프로그램** | 파일 시스템에 파일 접근 요청 |
| **논리적 파일 시스템** | 파일 메타데이터 및 디렉터리 관리, 파일 보호 및 접근 권한 관리 |
| **파일 조직화 모듈** | 파일의 논리적 블록과 물리적 블록 매핑, 블록 할당 및 빈 블록 관리 |
| **기본 파일 시스템** | 디스크 블록 단위의 읽기/쓰기, 버퍼 관리, I/O 요청 관리 |
| **입출력 제어** | 장치 드라이버를 통해 실제 I/O 장치를 제어, 인터럽트 처리 |
| **물리적 장치** | 실제 저장 장치에서 데이터 저장 및 읽기 |

## 파일 시스템 구성 요소
- **파티션**(Partition): 디스크를 논리적으로 나눠 놓은 것
- **볼륨**(Volume): 파일 시스템에 의해 관리되는 논리적 저장 영역

파일 시스템을 관리하기 위해 볼륨에는 다음과 같은 정보를 포함한다.

| 구성 요소 | 주요 역할 |
|---|---|
| **부트 제어 블록**(Boot Control Block) | 볼륨에서 운영체제를 부팅하는 데 필요한 정보를 저장 |
| **볼륨 제어 블록**(Volume Control Block) | 파일 시스템의 크기, 블록 수, 여유 공간 등 볼륨 및 파일 시스템에 대한 정보를 관리 |
| **디렉터리 구조**(Directory Structure) | 파일 이름과 해당 파일의 메타데이터를 연결하고 파일·디렉터리의 계층 구조를 관리 |
| **파일 제어 블록**(FCB, File Control Block) | 파일의 소유자, 크기, 접근 권한, 생성·수정 시간, 데이터 위치 등의 메타데이터를 관리 |
| **데이터 블록**(Data Blocks) | 실제 파일의 데이터와 디렉터리 데이터를 저장 |

파일 시스템은 파일 접근을 효율적으로 처리하기 위해 일부 관리 정보를 메모리에 유지한다.

| 자료 구조 | 주요 역할 |
|---|---|
| **메모리 마운트 테이블**(In-memory Mount Table) | 현재 마운트된 파일 시스템에 대한 정보를 관리 |
| **디렉터리 캐시**(Directory Cache) | 최근 접근한 디렉터리 정보를 메모리에 저장하여 디렉터리 검색을 빠르게 처리 |
| **시스템 전역 오픈 파일 테이블**(System-wide Open File Table) | 현재 시스템에서 열려 있는 파일에 대한 정보를 관리하며, 파일의 FCB 사본과 관련 정보를 포함 |
| **프로세스별 오픈 파일 테이블**(Per-process Open File Table) | 해당 프로세스가 열어 둔 파일에 대한 정보를 관리하며, 시스템 전역 오픈 파일 테이블의 항목을 가리키는 포인터 등을 포함 |

## 파일 시스템 구성 요소 간의 상호 작용
새 파일이 생성되면 새 **FCB**가 생성되고 메타데이터가 기록된다. 또한 해당 디렉터리에는 새 파일 이름과 파일을 식별할 수 있는 정보가 추가된다.

파일에 접근하기 위해 `open()` 시스템콜을 호출하면, 디스크에서 FCB 정보를 읽어와 메모리에 로드하고, **시스템 전역 테이블**에 새로운 항목을 만들어 로드한 FCB를 가리키도록 연결한다. 이후 **프로세스별 테이블**에 시스템 전역 테이블의 해당 항목을 참조하는 정보가 저장된다.

`open()` 시스템콜은 프로세스별 테이블의 인덱스를 반환한다. Unix에서는 이를 **파일 디스크립터**(File Descriptor)라고 하며, Windows에서는 **파일 핸들**(File Handle)이라고 한다.

다른 프로세스가 동일한 파일을 열고 있고 해당 파일을 공유할 수 있는 경우, 시스템 전역 테이블의 카운터(참조 수)가 증가하고, 새로운 프로세스의 테이블은 기존 항목을 참조한다.

파일이 닫히면 해당 프로세스의 테이블 항목이 해제되고, 시스템 전역 테이블 항목의 카운터(참조 수)가 감소한다. 해당 파일을 참조하는 프로세스가 더 이상 없으면 시스템 전역 테이블의 해당 항목도 해제될 수 있다.

파일의 변경된 데이터가 메모리에 남아 있는 경우에는 운영체제가 적절한 시점에 이를 디스크에 반영한다.

## 가상 파일 시스템(Virtual File System, VFS)
**VFS**는 사용자 공간의 애플리케이션과 실제 파일 시스템 구현 사이에 존재하는 추상화 계층으로, 여러 종류의 파일 시스템 유형에 공통 인터페이스를 제공한다.

애플리케이션이 `open()`, `read()`, `write()`, `mmap()`와 같은 표준 유닉스 시스템콜(POSIX API)을 사용하여 파일에 접근하면, 이를 해당 파일이 위치한 실제 파일 시스템이 이해할 수 있는 구체적인 명령으로 변환해 주는 역할을 한다.

이를 통해 애플리케이션은 파일 시스템의 종류(ext4, XFS, NFS 등)를 직접 알 필요 없이 동일한 인터페이스를 사용하여 파일에 접근할 수 있다.
