# 보호(Protection)
**보호**는 시스템 자원(객체)에 대한 접근을 통제하고, 자원 사용이 정의된 정책을 따르도록 보장하는 OS 메커니즘이다.

## 접근의 유형
일반적으로 다음과 같은 접근 권한을 설정할 수 있다.

| 권한 | 파일 | 디렉토리 |
|---|---|---|
| **r** | 파일의 내용을 읽을 수 있음 | 디렉터리의 항목을 조회할 수 있음 |
| **w** | 파일의 내용을 수정/삭제할 수 있음 | 디렉터리 내부에 파일이나 하위 디렉터리를 생성/삭제할 수 있음 |
| **x** | 파일을 실행할 수 있음 | 디렉터리 내부의 항목에 접근할 수 있음 |

## 접근 행렬(Access Matrix)
**접근 행렬**은 시스템의 **주체**(행)와 **객체**(열) 사이의 접근 권한을 표현하는 개념적 모델이다.
각 행렬의 엔트리에는 해당 주체가 객체에 대해 수행할 수 있는 접근 유형이 기록된다.

## 접근 행렬의 구현 방법
### 접근 제어 목록(Access Control List, ACL)
**ACL**은 객체(자원)을 중심으로 권한을 관리하는 방식이다.
각 객체에 접근할 수 있는 주체와 권한을 목록으로 저장한다.

```
파일 A
├─ Alice → r, w
└─ Bob → r
```

- **장점**: 특정 객체에 누가 어떤 권한을 가지고 있는지 확인하고 관리하기 쉽다. 파일 시스템 등 실제 운영체제에서 널리 사용된다.
- **단점**: 특정 주체가 어떤 객체에 어떤 권한을 가지고 있는지 전체적으로 파악하기 어렵다.

### 능력 리스트(Capability List)
**Capability List**는 주체(사용자)를 중심으로 접근권한을 관리하는 방식이다.
각 주체가 접근할 수 있는 객체와 해당 객체에 대해 허용된 권한을 목록으로 가진다.

```
Alice
├─ 파일 A → r, w
└─ 파일 B → r

Bob
└─ 파일 A → r
```

- **장점**: 권한 위임(Delegation)이 유연하고, 특정 주체가 가진 접근 권한을 확인하기 쉽다.
- **단점**: 객체나 주체가 많아지면 권한의 추적 및 관리가 복잡해질 수 있다.

## Unix/Linux의 권한 모델
Unix 계열 시스템에서는 일반적으로 파일의 권한을 소유자(Owner), 그룹(Group), 기타 사용자(Others)로 구분하여 관리한다.
```
-rwxr-x---
```
위 권한은 다음과 같이 해석할 수 있다.
```
rwx | r-x | ---
 ↓     ↓     ↓
소유자 그룹 기타사용자
```
