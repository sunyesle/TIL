# 운영체제의 지원에 의한 해결 방법
운영체제는 프로세스가 공유 자원에 안전하게 접근할 수 있도록 다양한 동기화 도구를 제공한다.

## 뮤텍스(Mutexes)
뮤텍스는 하나의 스레드만이 임계 영역에 접근할 수 있도록 제한하는 동기화 기법이다.

임계 영역에 들어가기 전에 락(lock)을 획득하고, 임계 영역을 벗어날 때 락을 해제한다.
락을 획득한 스레드만 해당 락을 해제할 수 있으며, 다른 스레드가 이미 락을 획득한 상태라면, 락을 요청한 스레드는 락이 해제될 때까지 대기한다.

임계 영역에 대한 단순한 상호 배제가 필요할 때 효과적이다.

## 세마포어(Semaphores)
세마포어는 여러 스레드가 공유 자원에 접근할 수 있도록 허용하면서, 접근 가능한 스레드의 수를 제한하는 동기화 기법이다.

정수값과 원자적 연산 `wait()`, `signal()`로 구성된다. 세마포어의 값은 현재 사용 가능한 공유 자원의 개수를 나타내며 0보다 크다면 공유 자원에 접근할 수 있다. 자원이 부족한 경우 스레드는 자원이 반환될 때까지 대기한다.

- `wait()`: 자원을 사용하기 전, 세마포어 값을 1 감소시키고 값이 0보다 작다면 대기한다.
- `signal()`: 자원을 반납할 때, 세마포어 값을 1 증가시키고 대기 중인 프로세스가 있다면 깨운다.

여러 개의 동일한 자원(버퍼, 커넥션 풀 등)에 대해 동시 접근 수를 제한해야 할 때 효과적이다.

## 모니터(Monitors)
모니터는 공유 자원에 대한 접근을 안전하게 관리하기 위해, 상호 배제와 조건 동기화를 함께 제공하는 고수준의 동기화 기법이다.

모니터는 락과 하나 이상의 조건 ​​변수로 구성된다.

락을 통해 모니터 내부에는 한 번에 하나의 스레드만 진입할 수 있도록 한다.

조건 변수는 특정 조건이 충족될 때까지 스레드가 대기하게 하거나, 조건이 충족됨을 스레드에게 알리는 동기화 도구이다.
이를 통해 특정 조건이 충족되지 않으면 스레드를 대기 상태로 만들고, 조건이 충족되면 다시 실행할 수 있도록 한다.

모니터는 동기화를 내부적으로 처리하기 때문에 개발자가 직접 락을 관리하지 않아도 된다.
