# 페이지 테이블의 구조
페이지 테이블의 크기가 너무 커지는 문제를 해결하고 관리 효율을 높이기 위해 다양한 페이지 테이블 구조화 기법이 사용된다.

## 계층적 페이징(Hierarchical Paging)
계층적 페이징은 하나의 페이지 테이블을 여러 단계의 페이지 테이블로 나누어 관리하는 방식이다.

상위 페이지 테이블은 하위 페이지 테이블의 위치를 가리키며, 하위 페이지 테이블은 실제 페이지가 저장된 프레임을 가리킨다.

계층을 나눌수록 페이지 테이블의 크기는 줄어들지만, 주소 변환에 필요한 메모리 접근 횟수가 증가한다.

## 해시 페이지 테이블(Hash Page Table)
**해시 페이지 테이블**은 페이지 번호를 해시하여 페이지 테이블 엔트리를 찾는 방식이다.

해시 테이블의 각 항목은 연결 리스트를 가지고 있으며, 연결 리스트의 각 엔트리는 페이지 번호, 매핑된 프레임 번호, 다음 엔트리 주소를 갖는다.

페이지 번호를 해시하여 테이블의 인덱스로 변환하고, 해당 엔트리에 연결된 연결 리스트를 탐색하여 페이지 번호와 일치하는 엔트리를 찾는다.

## 역 페이지 테이블(Inverted Page Tables)
**역 페이지 테이블**은 물리 프레임마다 하나의 엔트리를 갖도록 구성한 페이지 테이블이다.

테이블의 각 엔트리는 물리적 메모리의 하나의 프레임을 나타내며, 해당 프레임을 점유하고 있는 프로세스 ID, 페이지 번호 쌍이 저장된다.

페이지 테이블의 크기가 프로세스의 가상 주소 공간이 아닌 물리 메모리의 프레임 수에 비례한다.

하지만 프로세스 ID와 페이지 번호를 비교하며 순차 탐색해야 하므로 주소 변환 과정에서 탐색 비용이 발생한다.
