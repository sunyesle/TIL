# 파일 시스템의 복구
시스템 충돌(Crash)은 디렉터리, 아이노드, 빈 블록 리스트 등의 메타데이터를 비일관적인 상태로 만들어 데이터 무결성을 훼손할 수 있다.

## 일관성 검사(Consistency Checker)
**일관성 검사**는 시스템 부팅 또는 마운트 시 파일 시스템 전체의 구조적 일관성을 확인하고 복구하는 전통적인 방법이다.
디렉터리와 아이노드의 링크 수 및 블록 할당 정보를 비교하여 불일치를 찾고 수정한다. (ex: UNIX의 fsck, Windows의 chkdsk 또는 scandisk)

발견할 수 있는 오류는 다음과 같다.

- **블록 할당 오류**: 파일에 할당된 블록이 동시에 가용 블록 목록(Free List)에도 등록된 경우
- **미분류 블록**: 파일에 할당되지도 않고 가용 블록 목록에도 등록되지 않은 블록
- **중복 할당**: 하나의 디스크 블록이 둘 이상의 파일에 할당된 경우
- **파일 크기 불일치**: 파일에 할당된 블록 수와 파일에 기록된 크기가 일치하지 않는 경우
- **디렉터리 참조 누락**: 정상적으로 할당된 파일이나 inode가 어떤 디렉터리 항목에서도 참조되지 않는 경우
- **링크 수 불일치**: inode에 기록된 링크 수와 디렉터리 구조에서 해당 inode를 참조하는 횟수가 일치하지 않는 경우
- **파일 이름 중복**: 동일한 디렉터리 안에 같은 이름의 파일이 둘 이상 존재하는 경우
- **디렉터리 구조 오류**: 허용되지 않는 순환 참조가 존재하거나 루트 디렉터리에서 접근할 수 없는 파일 또는 디렉터리가 있는 경우
- **복구 파일 생성**: 일관성 검사기는 문제가 있는 블록을 chk00001.dat과 같은 파일로 모을 수 있다.

## 저널링 파일 시스템(Journaling File System)
**저널링 파일 시스템**은 파일 시스템의 변경 사항을 저널(Journal)이라는 로그에 먼저 기록하여, 시스템 충돌 후 파일 시스템의 일관성을 빠르게 복구할 수 있도록 하는 파일 시스템이다.

일반적으로 메타데이터 변경 사항을 저널에 기록하며, 저널링 방식에 따라 파일 데이터도 기록할 수 있다. (ex: ext3/4, NTFS)

- 특정 작업을 수행하기 위한 일련의 변경 사항을 **트랜잭션**이라고 한다.
- 트랜잭션의 변경 사항을 저널에 기록하고, **커밋**을 통해 트랜잭션의 기록이 완료 되었음을 표시한다.
- 커밋된 트랜잭션의 변경 사항은 실제 파일 시스템에 반영된다. 이 과정을 **체크포인트**라고 한다.
- 시스템 충돌이 발생하면 저널을 확인하여 커밋된 트랜잭션의 변경 사항을 재적용하고, 커밋되지 않은 트랜잭션은 일반적으로 복구 대상에서 제외한다.
- 변경 사항이 실제 파일 시스템에 반영되면 해당 저널 기록을 정리하고 공간을 재사용할 수 있다.

## 백업과 복구(Backup and Restore)
하드웨어 오류나 사용자 실수로 인한 데이터 손실을 방지하는 광범위한 개념이다.

- **백업**(Backup): 데이터를 별도의 안전한 저장소에 주기적으로 복사하는 과정이다.
- **복구**(Restore): 백업된 사본을 사용하여 손실된 데이터를 되돌리는 과정이다.

| 백업 유형 | 설명 | 복구에 필요한 백업 | 장단점 |
|---|---|---|---|
| **전체 백업** | 모든 데이터를 복사한다. | 최신 전체 백업 | 복구가 간단하지만 백업 시간과 저장 공간이 많이 필요하다. |
| **증분 백업** | 마지막 백업 이후 변경된 데이터만 복사한다. | 마지막 전체 백업 + 이후 모든 증분 백업 | 백업 시간과 저장 공간을 절약하지만 복구 과정이 복잡해질 수 있다. |
| **차등 백업** | 마지막 전체 백업 이후 변경된 모든 데이터를 복사한다. | 마지막 전체 백업 + 최신 차등 백업 | 증분보다 복구가 간단하다. |

전체 백업, 증분 백업, 차등 백업을 조합하여 백업 저장 공간, 복구에 필요한 백업 매체의 수, 복구 시간 사이의 균형을 찾을 수 있다.
