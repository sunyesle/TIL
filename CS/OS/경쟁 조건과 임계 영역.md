# 경쟁 조건과 임계 영역

## 경쟁 조건(Race Condition)
**경쟁 조건**은 둘 이상의 프로세스 또는 스레드가 동시에 공유 자원에 접근할 때, **접근 순서에 따라 결과가 달라질 수 있는 상황**을 말한다.

### 예시
다음은 두 개의 스레드가 하나의 공유 자원 `counter`의 값을 동시에 증가시키려고 할 때 발생할 수 있는 경쟁 조건의 예시이다.

**공유 자원**
```c
int counter = 0; // 공유 자원
```

**스레드 함수**
```c
void* incrementCounter(void* arg) {
    int i;
    for (i = 0; i < 1000000; i++) {
        counter++; // 공유 자원 증가
    }
    return NULL;
}
```

**메인 함수**
```c
#include <pthread.h>
#include <stdio.h>

int main() {
    pthread_t thread1, thread2;

    // 스레드 생성, incrementCounter 함수를 실행
    pthread_create(&thread1, NULL, incrementCounter, NULL);
    pthread_create(&thread2, NULL, incrementCounter, NULL);

    // 스레드가 종료될 때까지 기다림
    pthread_join(thread1, NULL);
    pthread_join(thread2, NULL);

    // 최종 counter 값 출력
    printf("Final counter value: %d\n", counter);
    return 0;
}
```

각 스레드는 `counter` 변수를 `1,000,000`번씩 증가시키려고 시도한다. 이상적으로는 프로그램이 종료될 때 `counter`의 값이 `2,000,000`이 되어야 하지만 경쟁 조건으로 인해 이보다 작은 값이 출력될 수 있다.

이는 `counter++` 연산이 원자적(atomic)이지 않기 때문이다. `counter++` 연산은 읽기, 증가, 쓰기 세 단계로 구성되어 있으며 이 단계들 사이에 다른 스레드가 끼어들어 `counter`의 값을 변경할 수 있다.

- **읽기**: `counter`의 현재 값을 메모리(또는 캐시)에서 읽어온다.
- **증가**: 읽어온 값에 1을 더한다.
- **쓰기**: 계산된 값을 다시 `counter`에 저장한다.

만약 두 스레드(스레드1, 스레드2)가 동시에 실행하면 다음과 같은 문제가 발생할 수 있다.

- 스레드1이 `counter`의 값을 읽는다. (counter = 0)
- 스레드2가 `counter`의 값을 읽는다. (counter = 0)
- 스레드1이 `counter`에 1을 더한 값을 계산하고, 값을 쓴다. (counter = 1)
- 스레드2가 `counter`에 1을 더한 값을 계산하고, 값을 쓴다. (counter = 1)

`counter++`는 두 번 실행되었지만, `counter` 값은 1만 증가하는 현상이 발생한다.

## 임계 영역(Critical Section)
**임계 영역**은 둘 이상의 프로세스 또는 스레드가 **공유 자원에 접근하거나 변경하는 코드 영역**을 말한다.

공유 자원은 전역 변수, 파일, 메모리 등이 될 수 있으며, 데이터의 일관성과 무결성을 유지하기 위해 해당 자원에 대한 독점적인 접근이 보장되어야 한다.
즉, 공유 자원에 동시에 접근하여 변경해서는 안 되며, 경쟁 조건을 방지하기 위해 동기화가 필요하다.

위 예시에서는 `counter`라는 공유 자원을 변경하는 `counter++;`라는 코드 영역이 이에 해당된다.
