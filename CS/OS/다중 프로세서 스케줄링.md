# 다중 프로세서 스케줄링
**다중 프로세서 스케줄링**은 둘 이상의 CPU 또는 코어를 가진 시스템에서 프로세스/스레드를 프로세서에 할당하는 작업이다. 부하 분산과 데이터 지역성 유지가 중요하다.

## 접근 방식
- **비대칭 다중 처리**(Asymmetric Multiprocessing): 하나의 CPU가 주 프로세서(Master)로 모든 스케줄링 및 자원 관리를 전담하며, 나머지 CPU는 주 프로세서가 할당한 작업을 수행한다.
- **대칭 다중 처리**(SMP, Symmetric Multiprocessing): 모든 프로세서가 동일한 역할을 수행하며 독립적으로 스케줄링한다. 데이터 동기화가 필요하지만, 부하 분산과 확장성이 뛰어나다.

## 프로세서 선호도
**프로세서 선호도**는 특정 프로세스가 이전에 실행되었던 프로세서에서 계속 실행되기를 선호하는 경향이다. 이는 CPU의 캐시 지역성을 활용하여 성능을 향상시키기 위해 사용된다.

프로세서에는 캐시 메모리가 포함되어 있으며, 최근 접근한 데이터나 인접한 데이터를 저장하여 메모리 접근 속도를 향상시킨다.

만약 프로세스가 CPU를 할당받을 때마다 다른 프로세서로 이동한다면, 이전 프로세서의 캐시 데이터를 활용하지 못해 캐시 미스가 발생하고, 필요한 데이터를 다시 로드해야 하므로 성능 저하가 발생한다.

따라서 SMP 시스템에서는 프로세서 선호도를 통해 프로세스가 가능한 한 동일한 프로세서에서 실행되도록 한다.

- **소프트 선호도**(Soft Affinity): 가능하면 같은 프로세서에서 실행
- **하드 선호도**(Hard Affinity): 특정 프로세서에서만 실행하도록 제한

## 부하 분산
**부하 분산**은 여러 프로세서 간의 부하 불균형을 줄이고 CPU 활용률을 높이기 위해 작업을 분배하는 기술이다.

- **푸시 마이그레이션**(Push Migration): 별도의 부하 분산 작업이 주기적으로 실행되어 부하가 높은 프로세서의 작업을 부하가 낮은 프로세서로 이동시킨다.
- **풀 마이그레이션**(Pull Migration): 유휴 프로세서가 다른 프로세서의 준비 큐에서 작업을 가져온다.

프로세스 이동을 통한 부하 분산은 프로세서 선호도 원칙과 상충하며, 신중하게 관리하지 않으면 부하 분산의 이득보다 캐시 미스로 인한 손실이 더 커질 수 있다.

이에 대한 해결책으로, 불균형이 특정 임계값을 초과할 때만 프로세스 이동을 허용하는 방식을 사용할 수 있다.
