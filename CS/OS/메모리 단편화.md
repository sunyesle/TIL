# 메모리 단편화
메모리를 할당하는 과정에서 사용하지 못하거나 낭비되는 공간이 발생하는 현상이다.

## 내부 단편화(Internal Fragmentation)
요청한 메모리보다 큰 블록을 할당받아 메모리 블록 내에서 실제로 사용되지 않고 낭비되는 공간이 발생하는 것을 말한다.

ex) 10MB의 메모리를 할당해 줬지만, 실제 프로세스는 5MB만 사용하는 경우, 내부 단편화가 5MB 생기게 된다.

<img src="https://github.com/user-attachments/assets/cc984696-3548-4b4e-917e-a3f46f900db1" width="400"/>

### 발생 원인
- **고정 크기 메모리 할당**: 메모리를 일정한 크기의 블록으로 나누어 할당할 때, 요청한 크기보다 큰 블록이 할당되어 내부에 남는 공간이 발생할 수 있다.
- **메모리 정렬과 패딩**: 데이터 정렬을 위해 빈 공간이 추가되어 내부 단편화가 발생할 수 있다.

### 해결 방법
필요한 만큼 메모리를 할당하는 가변 크기 메모리 할당 방식을 사용한다.

## 외부 단편화(External Fragmentation)
사용 가능한 총 메모리는 충분하지만, 요청한 메모리 크기를 담을 수 있는 연속된 메모리 공간이 존재하지 않아 메모리를 할당할 수 없는 상황을 말한다.

ex) 남는 메모리 공간은 5MB + 5MB = 10MB지만, 10MB의 메모리가 필요한 프로세스가 할당받을 공간이 없다.

<img src="https://github.com/user-attachments/assets/c13ffcd3-241c-4a9c-b8a1-e8ee505f4a90" width="600"/>

### 발생 원인
프로세스의 할당과 해제가 반복되면서 가용 메모리 공간이 여러 개의 작은 공간으로 나뉠 때 발생한다.

### 해결 방법
- **압축**: 메모리 재배치를 통해 흩어진 가용 공간을 하나의 큰 블록으로 모은다.
- **페이징**: 프로세스를 페이지 단위로 쪼갠 다음 각 페이지를 메모리에 할당한다. 페이지들은 연속적으로 배치될 필요가 없기 때문에 충분한 메모리 공간만 있다면 외부 단편화는 발생하지 않는다.
