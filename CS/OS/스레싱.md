# 스레싱(Thrashing)
**스레싱**은 프로세스가 실행되는 시간보다 페이지를 교체하는 데에 더 많은 시간을 사용하는 비효율적인 상태이다.

## 발생 원인
초기 프로세스 스케줄링 방식은 CPU 사용률을 기반으로 다중프로그래밍 허용 수준을 제어하여 CPU 사용률이 낮을 때 더 많은 프로세스를 추가했다.

문제는 메모리가 가득 차고 프로세스들이 페이지 로딩을 기다리는 데 많은 시간을 소비하게 되면 CPU 사용률이 낮아지고, 이로 인해 스케줄러가 더 많은 프로세스를 추가하여 문제를 악화시킨다는 점이다.

## 작업 집합 모델(Working-Set Model)
각 프로세스에게 지역성(Locality)에 기반하여 필요한 만큼의 프레임을 할당함으로써 스레싱을 방지하는 방법이다.

**작업 집합**이란 프로세스의 최근 △개의 페이지 참조에 들어있는 페이지 집합을 말한다.

운영체제는 각 프로세스의 작업 집합을 파악하여, 모든 프로세스의 작업 집합을 메모리에 유지할 수 있는지 판단한다.
모든 프로세스의 작업 집합 크기의 합이 총 프레임 수보다 커지면 메모리가 부족해져 스레싱이 발생할 수 있으므로, Swap-out을 통해 다중 프로그래밍 정도를 낮춰 이를 예방한다.

## 페이지 부재 빈도(Page-Fault Frequency, PFF)
프로세스의 페이지 부재 발생률을 모니터링하여 프레임 할당량을 동적으로 조절하는 방법이다.

페이지 부재율이 높다는 것은 그 프로세스가 더 많은 프레임을 필요로 한다는 것을 의미하고, 페이지 부재율이 낮다는 것은 할당된 프레임이 상대적으로 많을 수 있음을 의미한다.

페이지 부재율의 상한선과 하한선을 정해놓고, 페이지 부재율이 상한선을 넘으면 더 많은 프레임을 할당, 페이지 부재율이 하한선보다 낮아지면 프레임을 회수한다.

## 비교
|        | 작업 집합 모델                | 페이지 부재 빈도             |
| ------ | ----------------------- | --------------------- |
| **기준**     | 최근 참조한 페이지 집합      | 페이지 부재 발생률        |
| **판단**     | 실행에 필요한 페이지가 얼마나 많은가? | 페이지 부재가 얼마나 자주 발생하는가? |
| **조절 대상** | 프로세스 수 | 프로세스의 프레임 수 |
