# 페이지 교체(Page Replacement)
요구 페이징은 요구되는 페이지만 보조기억장치에서 가져온다.
하지만 프로그램들을 실행함에 따라 요구 페이지도 계속 늘어나게 되고, 그러다 보면 언젠가는 메모리가 가득 차게 될 것이다.

**페이지 교체**는 페이지 부재 발생 시 메모리 공간을 확보하기 위해 현재 메모리에 있는 페이지 중 하나를 선택하여 보조기억장치로 내보내는 과정이다.

페이지 교체 과정은 다음과 같다.

1. 필요한 페이지가 메모리에 없으면 페이지 부재가 발생한다.
2. 운영체제는 메모리에서 교체할 페이지(Victim Page)를 선택한다.
3. 교체할 페이지의 수정 비트(Dirty Bit)를 확인하여 페이지가 수정된 경우 보조기억장치에 변경된 내용을 저장한다.(Write-Back)
4. 선택한 페이지를 프레임에서 제거하고, 필요한 페이지를 해당 프레임에 적재한다.
5. 페이지 테이블을 업데이트한다.
6. 중단된 명령어를 재실행한다.

## 페이지 교체 알고리즘
요구 페이징의 성능은 페이지 부재율에 크게 영향을 받는다. 페이지 부재가 발생하면 보조기억장치에서 해당 페이지를 메모리로 적재하기 위한 디스크 I/O가 발생하므로, 일반적인 메모리 접근보다 훨씬 많은 시간이 소요된다.
따라서 성능 저하를 줄이기 위해서는 페이지 부재율을 최대한 낮추는 것이 중요하다.

페이지 교체 알고리즘의 주요 목표는 페이지 부재율을 최소화하는 것이다.

### 1. FIFO 페이지 교체(First In, First Out)
메모리에 가장 먼저 적재된 페이지를 교체한다.

### 2. 최적 페이지 교체(Optimal Page Replacement, OPT)
앞으로 가장 오랫동안 사용되지 않을 페이지를 교체한다.
이론적으로 가장 적은 페이지 폴트를 발생시키지만, 미래의 메모리 접근을 알아야 하므로 실제 시스템에서는 구현하기 어렵다. 성능 평가의 기준으로 사용된다.

### 3. LRU 페이지 교체(Least Recently Used)
가장 오랫동안 사용되지 않은 페이지를 교체한다.
시간 지역성 원리에 기반하며, OPT에 가까운 성능을 보인다.
정확한 LRU 구현은 모든 메모리 참조를 추적해야 하므로 오버헤드 크며, 일반적으로 하드웨어의 지원이 필요하다.

- **카운터**: 페이지에 접근할 때마다 현재 카운터(논리적 시계) 값을 해당 페이지 테이블 엔트리에 저장한다. 카운터 값이 가장 작은 페이지를 교체한다.
- **스택**: 페이지에 접근할 때마다 해당 페이지를 스택의 맨 위로 이동시킨다. 스택의 맨 아래에 있는 페이지를 교체한다.

### 4. LRU 근사 페이지 교체(LRU Approximation)
정확한 LRU 구현의 과도한 오버헤드를 줄이기 위해, 하드웨어가 제공하는 참조 비트(Reference Bit) 등을 이용하여 LRU 알고리즘과 근사하게 구현한 페이지 교체 알고리즘들이 존재한다.

#### 참조 비트
각 페이지에 참조 비트를 두어 최근에 해당 페이지가 참조되었는지를 기록한다.

페이지가 참조되면 해당 페이지의 참조 비트를 1로 설정하며, 운영체제는 주기적으로 참조 비트를 0으로 초기화하여 이후 페이지가 다시 참조되었는지를 확인할 수 있도록 한다. 참조 비트가 0인 페이지를 우선적으로 교체한다.

#### 부가적 참조 비트 알고리즘
각 페이지마다 일정한 크기의 참조 비트를 두어 최근의 참조 기록을 저장한다.

일정한 주기마다 시프트 연산을 진행하고, 현재 참조 비트를 맨 왼쪽 최상위 비트(MSB)에 복사한다. 참조 비트가 가장 작은 페이지를 교체한다.
```
초기       00000000
참조       10000000
다음 주기  01000000
다음 주기  00100000
```

#### 2차 기회 알고리즘
FIFO 알고리즘을 개선한 방식으로, 참조 비트를 활용하여 최근에 참조된 페이지가 교체되지 않고 한 번 더 메모리에 유지될 기회를 제공한다.

- 참조 비트가 **0**이면 해당 프레임의 페이지를 교체한다.
- 참조 비트가 **1**이면 0으로 변경하여 다시 한번 기회를 부여하고, 다음 FIFO 페이지로 넘어간다.

#### 개선된 2차 기회 알고리즘
2차 기회 알고리즘을 개선한 방식으로, 참조 비트와 수정 비트를 함께 활용하여 교체할 페이지를 결정한다.

(참조 비트, 수정 비트) 순서에 따라 4가지 등급으로 분류하며, 낮은 등급의 페이지를 우선적으로 교체한다.
1. **(0, 0)** : 참조되지도 않고 변경되지도 않은 경우 - 교체하기 가장 적합한 페이지
2. **(0, 1)** : 참조되지 않았지만 변경은 된 경우 - 교체를 위해 보조기억장치에 내용을 저장해야 함
3. **(1, 0)** : 참조되었으나 변경은 되지 않은 경우 - 다시 사용될 가능성이 높음
4. **(1, 1)** : 참조되었고 변경도 된 경우 - 교체 대상으로 선택하지 않는 것이 좋음

## 페이지 버퍼링 알고리즘
페이지 교체 성능을 개선하기 위한 기법으로, 위에서 언급한 알고리즘과 함께 사용된다.

- **빈 프레임 풀 유지**
   - 항상 일정 수의 빈 프레임(Free Frame)을 유지하고, 페이지 폴트가 발생하면 우선 빈 프레임에 필요한 페이지를 적재하여 빠르게 프로세스를 재개한다. 이후 백그라운드에서 교체할 페이지(Victim Page)를 선택하고 처리하여 다시 빈 프레임을 확보한다.
- **수정된 페이지 미리 저장**
   - 수정된 페이지를 입출력 장치가 유휴 상태일 때 미리 보조기억장치에 저장하고 해당 페이지의 수정 비트 지운다. 페이지 교체가 발생했을 때 페이지를 보조기억장치에 저장하는 작업을 줄일 수 있다.
- **최근 교체된 페이지 유지**
   - 빈 프레임 풀에 들어간 페이지의 내용을 곧바로 지우지 않고 어떤 페이지인지 기억하고 있는다. 해당 페이지가 다시 필요해지면 보조기억장치에서 다시 읽어오지 않고 즉시 사용할 수 있다.
