# 입출력 처리 방식
## 프로그램 기반 I/O(Programmed I/O)
**프로그램 기반 I/O**는 CPU가 직접 장치의 상태를 확인하고 I/O 작업을 수행하는 방식이다. 일반적으로 **폴링**(Polling)을 사용하여 장치의 상태 레지스터를 주기적으로 확인하여 I/O 작업의 완료 여부를 확인한다.

장치가 준비될 때까지 CPU가 상태 레지스터를 반복해서 확인해야 하므로, Busy Waiting이 발생할 수 있다.

## 인터럽트 기반 I/O(Interrupt-driven I/O)
**인터럽트 기반 I/O**는 장치가 I/O 작업의 완료나 특정 이벤트가 발생했음을 CPU에 알리는 방식이다.

CPU가 장치의 상태를 계속 확인할 필요가 없으므로, 장치가 준비되는 동안 CPU는 다른 작업을 수행할 수 있다.
장치에서 인터럽트가 발생하면 CPU는 현재 실행 중인 작업을 잠시 중단하고 인터럽트 서비스 루틴(ISR)​을 실행하여 해당 I/O 요청을 처리한다.

## 직접 메모리 접근(Direct Memory Access, DMA)
**DMA**는 CPU가 데이터를 직접 전송하는 대신, DMA 컨트롤러가 입출력 장치와 메모리 사이의 데이터 전송을 수행하는 방식​이다.

CPU는 DMA 컨트롤러에 메모리 시작 주소, 전송할 데이터의 크기, 입출력 장치 등의 정보를 설정하고 전송을 요청한다. 이후 DMA 컨트롤러가 장치와 메모리 사이에서 데이터를 전송하며, 전송이 완료되면 CPU에 인터럽트를 발생시켜 완료 사실을 알린다.

CPU는 데이터 전송을 DMA 컨트롤러에 맡기고 다른 작업을 수행할 수 있기 때문에, CPU의 I/O 처리 부담을 줄일 수 있다.

### DMA 구성 요소
- **주소 레지스터**(Address Register): DMA 전송에 사용할 메모리 주소
- **데이터 레지스터**(Data Register): 전송 데이터를 임시로 저장하는 버퍼
- **계수 레지스터**(Counter Register): 전송할 데이터의 개수 또는 남은 전송량
- **컨트롤 레지스터**(Control Register): 전송 방향, 전송 모드 및 전송 시작 등을 제어
- **제어 회로**: DMA 전송을 제어하고 필요한 제어 신호를 생성

### 사이클 스틸링(Cycle Stealing)
**사이클 스틸링**은 DMA 컨트롤러가 CPU와 메모리 버스를 공유하면서, CPU의 메모리 버스 사용 사이클을 일시적으로 확보하여 데이터 전송에 사용하는 방식이다.

CPU와 DMA 컨트롤러는 메모리 버스를 통해 메모리에 접근하지만, 두 장치가 동시에 사용할 수 없다.
DMA 컨트롤러가 데이터를 전송하기 위해 메모리 버스 사용을 요청하면, CPU가 메모리 버스를 사용하는 사이클 중 일부를 DMA 컨트롤러에 양보한다.

CPU가 메모리 버스를 사용하지 않는 작업을 수행하고 있다면 DMA가 메모리에 접근하는 동안 CPU도 명령어를 실행할 수 있다.

### 전송 모드
- **사이클 스틸링 모드**: DMA가 버스 사이클을 하나씩 확보하여 워드 단위로 전송
- **버스트 모드**(Burst Mode): DMA가 버스를 확보한 후 블록 전체를 전송
- **투명 모드**(Transparent Mode): CPU가 버스를 전혀 쓰지 않는 유휴 시간에만 전송
