# 응용 입출력 인터페이스(Application I/O Interface)
응용 입출력 인터페이스는 응용 프로그램이 입출력 장치에 접근할 때 사용하는 공통 인터페이스이다.
운영체제는 `read()`, `write()` 등의 시스템콜을 통해 장치 유형에 관계없이 일관된 방식으로 입출력 장치에 접근할 수 있도록 한다.

## 입출력 장치의 특성
| 분류 기준 | 종류 | 예시 |
|---|---|---|
| **데이터 전송 단위** | 문자 단위<br>블록 단위 | 터미널<br>디스크 |
| **접근 방식** | 순차 접근(sequential)<br>임의 접근(random) | 모뎀<br>CD-ROM |
| **전송 방식** | 동기(synchronous)<br>비동기(asynchronous) | 테이프<br>키보드 |
| **공유 여부** | 전용(dedicated)<br>공유(sharable) | 테이프<br>키보드 |
| **장치 속도** | 지연 시간<br>탐색 시간<br>전송률<br>연산 간 지연 시간 | |
| **입출력 방향** | 읽기 전용<br>쓰기 전용<br>읽기/쓰기 | CD-ROM<br>그래픽 컨트롤러<br>디스크 |

## 블록 장치와 문자 장치
| | 블록 장치 (Block Device) | 문자 장치 (Character Device) |
|---|---|---|
| **데이터 전송 단위** | 블록 단위 (고유 주소 가짐) | 바이트 단위 (주소 지정 불가능) |
| **접근 방식** | 임의 접근(Random Access) 가능 | 순차 접근(Sequential Access)만 가능 |
| **예시** | 하드 디스크, SSD | 키보드, 마우스, 프린터 |

## 네트워크 장치
네트워크 통신은 로컬 디스크 접근과 본질적으로 다르기 때문에 네트워크 장치용으로 별도의 인터페이스를 사용한다.

널리 사용되는 것은 **소켓**(Socket) 인터페이스로 데이터를 한쪽 끝에서 소켓에 입력하고 다른 쪽 끝에서 순차적으로 읽어낼 수 있다.
소켓은 일반적으로 양방향 데이터 전송을 지원하는 전이중 방식이다.

## 클록과 타이머
- **클록**(Clock): 일정한 주파수로 전류를 보내는 하드웨어로 시스템의 기본 시간 단위를 제공한다.
- **타이머**(Timer): PIT(Programmable Interval Timer)은 특정 시간 간격으로 인터럽트를 발생시키도록 설정하는 장치로, CPU 스케줄링 등에 필수적이다.

## 블로킹과 논블로킹 입출력
시스템콜 완료 시까지 프로세스 대기 여부에 따른 입출력 모델이다.

| | Blocking I/O | Nonblocking I/O |
|---|---|---|
| **원리** | I/O 완료 시까지 프로세스가 블록 상태로 전환되어 대기한다. | I/O 요청 즉시 제어권을 응용 프로그램에 반환한다. |
| **장점** | 프로그래밍이 단순하다. | CPU 활용률이 높다. |

## 벡터 입출력 (Vectored I/O, Scatter-Gather I/O)
**벡터 입출력**은 한 번의 시스템콜로 여러 버퍼에 데이터를 읽거나 쓰는 입출력 방식이다.

- `readv()`: 하나의 파일 디스크립터에서 데이터를 읽어서, 여러 개의 버퍼에 분산하여 저장한다. (Scatter)
- `writev()`: 여러 개의 메모리 버퍼에 나누어져 있는 데이터를 모아서, 하나의 파일 디스크립터에 한 번에 기록한다. (Gather)

벡터 입출력은 선형 입출력 방식에 비해 다음과 같은 장점이 있다.

- 데이터가 여러 버퍼에 자연스럽게 분리되어 있다면 별도의 버퍼 복사 없이 직관적으로 처리할 수 있다.
- 한 번의 벡터 입출력 연산으로 여러 번의 선형 입출력 연산을 대체하여 시스템콜 호출 횟수를 줄일 수 있다.
