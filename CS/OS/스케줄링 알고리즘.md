# 스케줄링 알고리즘

## 비선점형 스케줄링
**비선점형 스케줄링**(Non-Preemptive)은 CPU를 할당받은 프로세스가 자발적으로 CPU를 반납할 때까지 다른 프로세스가 CPU를 빼앗을 수 없는 방식이다.

실행 중인 프로세스가 종료되거나 I/O 요청 등으로 CPU를 반납할 때까지 다른 프로세스는 CPU를 할당받을 수 없다.
컨텍스트 스위칭으로 인한 부하가 적고 구현이 단순하지만, 긴 작업이 CPU를 점유하면 다른 프로세스의 대기 시간이 증가하는 **호위 효과**(Convoy Effect)가 발생할 수 있으며 응답성이 낮다.

### 1. 선입 선처리 스케줄링(FCFS, First Come First Served)
준비 큐에 도착한 순서대로 CPU를 할당하는 방식이다.

### 2. 최단 작업 우선 스케줄링(SJF, Shortest Job First)
CPU 점유 시간이 가장 짧은 프로세스부터 CPU를 할당하는 방식이다.

### 3. 최고 응답 우선 스케줄링(HRRN, Highest Response Ratio Next)
CPU 점유 시간과 대기 시간을 고려하여 우선순위를 부여하고 우선순위에 따라 CPU를 할당하는 방식이다. SFJ 스케줄링에서 발생할 수 있는 *아사 현상*을 해결하기 위해 만들어졌다.

> **아사 현상**<br>
> 우선순위가 높은 프로세스가 지속적으로 자원을 차지하면서, 우선순위가 낮은 프로세스가 자원을 할당받지 못하고 무기한 대기하게 되는 현상

## 선점형 스케줄링
**선점형 스케줄링**(Preemptive)은 어떤 프로세스가 CPU를 할당받아 실행 중이더라도 운영체제가 이를 강제로 뺏을 수 있는 스케줄링 방식이다.

실행 상태에 있는 작업을 중단시키고 새로운 작업을 실행할 수 있다.
한 프로세스가 CPU를 장시간 독점하는 것을 막을 수 있지만, 잦은 컨텍스트 스위칭으로 인해 오버헤드가 커질 수 있다.

### 1. 라운드 로빈(Round Robin)
각 프로세스에게 동일한 시간 할당량(Time Quantum)을 순서대로 할당하는 선점형 스케줄링 방식이다.
프로세스는 할당받은 시간 동안 CPU를 사용하며, 시간이 만료되기 전에 작업을 완료하지 못하면 강제로 선점되어 준비 큐의 맨 뒤로 이동하고 다시 자신의 차례를 기다린다.
시간 할당량이 너무 크면 비선점형 FCFS와 유사해지고, 너무 작으면 컨텍스트 스위칭 오버헤드가 증가한다.

### 2. 최단 잔여 시간 우선 스케줄링(SRT, Shortest Remaining Time)
SJF 스케줄링의 선점형 버전으로 남은 실행 시간이 가장 짧은 다른 프로세스에 CPU를 먼저 할당한다. 실행 중인 프로세스보다 남은 시간이 더 짧은 프로세스가 도착하면, 현재 프로세스의 CPU를 빼앗아 새 프로세스에게 먼저 할당한다.

### 3. 우선순위 스케줄링(Priority Scheduling)
각 프로세스에 우선순위를 부여해 우선순위가 높은 프로세스를 먼저 실행시키는 방식이다. 실행 중인 프로세스보다 우선순위가 더 높은 프로세스가 도착하면, 현재 프로세스의 CPU를 빼앗아 새 프로세스에게 먼저 할당한다.

### 4. 다단계 큐 스케줄링(Multilevel Queue)
여러 개의 준비 큐를 만들어 프로세스를 고정적으로 분류하고, 각 큐마다 독립적인 스케줄링 정책을 적용하는 방식이다.

**큐 간의 스케줄링 방식**
- **고정 우선순위 방식**: 큐마다 고정된 우선순위를 부여하고, 높은 우선순위 큐의 프로세스에 CPU를 먼저 할당한다. 낮은 우선순위 큐의 프로세스는 기아 현상이 발생할 수 있다.
- **라운드 로빈 방식**: 각 큐에 일정한 CPU 시간 비율을 할당하여 순차적으로 실행한다.

큐들 간의 프로세스 이동이 불가능하기 때문에 구현이 단순하고 스케줄링 부담이 적지만, 유연성이 떨어지고 기아 현상이 발생할 수 있다.

### 5. 다단계 피드백 큐 스케줄링(Multilevel Feedback Queue)
다단계 큐의 단점을 보완하여, 프로세스가 큐 사이를 이동할 수 있도록 만든 스케줄링 방식이다. 일반적으로 상위 큐일수록 높은 우선순위를 가지며 시간 할당량이 작다.

**기본 동작 방식**
- 새 프로세스는 가장 높은 우선순위 큐에 배치한다.
- 프로세스가 타임 슬라이스를 모두 사용한다면 하위 큐로 이동한다. (CPU-bound 프로세스는 점점 낮은 우선순위 큐로 이동)
- 프로세스가 타임 슬라이스를 다 사용하지 않고 CPU를 반납한다면 상위 큐로 이동한다. (I/O bound 프로세스는 점점 높은 우선순위 큐로 이동)
- 하위 큐 프로세스의 기아상태를 방지하기 위해, 오래 대기한 프로세스는 상위 큐로 이동한다. (Aging 기법)
