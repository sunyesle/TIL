# CPU 스케줄링
**CPU 스케줄링**은 준비 상태에 있는 프로세스 중 어떤 프로세스에게 CPU를 할당해 줄지 결정하는 작업이다. CPU에서 프로세스를 할당하고 회수함으로써 CPU 효율을 높이는 것을 목표로 한다.

## CPU-I/O 버스트 사이클
거의 모든 프로세스는 CPU를 사용하는 시간과 I/O 장치 사용을 위해 대기하는 시간 두 상태를 번갈아 가며 진행된다.

## CPU 스케줄러
**CPU 스케줄러**는 준비 상태에 있는 프로세스 중에서 CPU를 할당받아 실행할 다음 프로세스를 선택하는 역할을 한다.

스케줄링은 다음과 같은 상황에 발생한다.
- 실행 -> 대기 (I/O 요청, wait() 시스템 호출)
- 실행 -> 준비 (인터럽트)
- 대기 -> 준비 (I/O 완료, wait() 반환)
- 실행 -> 종료

## 디스패처 (Dispatcher)
**디스패처**는 스케줄러가 선택한 프로세스에게 CPU 제어권을 넘겨주는 모듈이다.

디스패처는 다음 기능을 수행한다.
- 컨텍스트 스위칭
- 사용자 모드로 전환
- 프로그램 카운터(PC)를 해당 프로세스의 실행 위치로 설정

**디스패치 지연 시간**(Dispatch latency)은 실행 중이던 프로세스를 정지시키고, 다른 프로세스에 CPU를 할당해 실행을 시작하기까지 걸리는 시간이다.

## 선점형/비선점형 스케줄링

|  | 선점형 스케줄링 | 비선점형 스케줄링 |
|---|---|---|
| **정의** | CPU를 강제로 회수하여 다른 프로세스에 할당할 수 있는 방식 | CPU를 할당받은 프로세스가 자발적으로 반환할 때까지 회수할 수 없는 방식 |
| **특징** | 높은 응답성을 제공하나, 컨텍스트 스위칭으로 인한 오버헤드가 크다. | 구현이 단순하고 오버헤드가 적지만, 긴 작업으로 인해 대기 시간이 증가할 수 있다. |
| **사용 환경** | 시분할 시스템, 실시간 시스템 등 대화형 환경 | 배치 처리 시스템 |
