# 입출력 하드웨어
입출력 장치는 종류와 동작 방식이 매우 다양하기 때문에, 운영체제는 공통적인 하드웨어 구조와 인터페이스를 통해 장치를 제어한다.

## 입출력 장치의 구성
- **포트**(Port): 장치가 컴퓨터와 통신하기 위한 연결 지점이다.
- **버스**(Bus): CPU, 메모리, 입출력 장치 등이 데이터를 주고받을 수 있도록 연결하는 통신 경로이다.
- **장치 컨트롤러**(Device Controller): CPU와 입출력 장치 사이의 통신을 담당하는 하드웨어이다. 장치의 동작을 제어하며, CPU와 장치 사이에서 데이터를 전달한다.

## 장치 컨트롤러의 레지스터
장치 컨트롤러는 상태, 제어, 데이터 등을 저장하기 위한 레지스터를 제공한다.
CPU는 이 레지스터를 읽거나 쓰면서 장치를 제어하고 데이터를 주고받는다.

- **상태 레지스터**(Status Register): CPU가 읽는 레지스터로, 현재 명령의 완료 여부, 입력 레지스터에서 데이터를 읽을 수 있는지 여부, 오류 발생 여부 등의 장치 상태를 나타낸다.
- **제어 레지스터**(Control Register): CPU가 쓰는 레지스터로, 장치에 입출력 명령을 내리거나 장치의 동작 모드를 설정한다.
- **데이터 입력 레지스터**(Data-in Register): CPU가 읽는 레지스터로, 장치에서 입력된 데이터를 가져온다.
- **데이터 출력 레지스터**(Data-out Register): CPU가 쓰는 레지스터로, 장치로 출력할 데이터를 전달한다.

## 주소 매핑 방식
### Memory-Mapped I/O
입출력 장치 컨트롤러의 레지스터와 버퍼가 CPU의 물리적 메모리 주소 공간의 일부에 매핑되는 방식이다.

CPU 입장에서는 장치 레지스터가 메모리 주소 공간에 매핑되어 있으므로 일반적인 메모리 읽기/쓰기 명령어를 사용하여 입출력 장치를 제어할 수 있다.

### I/O-Mapped I/O
입출력 장치 컨트롤러의 레지스터와 버퍼가 메모리 주소 공간 독립된 별도의 I/O 주소 공간에 매핑되는 방식이다.

`IN`, `OUT`과 같은 I/O 전용 특수 명령어를 사용하여 입출력 장치를 제어한다.

## I/O 처리 방식
### 프로그램 기반 I/O(Programmed I/O)
**프로그램 기반 I/O*는 CPU가 직접 장치의 상태를 확인하고 I/O 작업을 수행하는 방식이다. 일반적으로 **폴링**(Polling)을 사용하여 장치의 상태 레지스터를 주기적으로 확인하여 I/O 작업의 완료 여부를 확인한다.

장치가 준비될 때까지 CPU가 상태 레지스터를 반복해서 확인해야 하므로, Busy Waiting이 발생할 수 있다.

### 인터럽트 기반 I/O(Interrupt-driven I/O)
**인터럽트 기반 I/O**는 장치가 I/O 작업의 완료나 특정 이벤트가 발생했음을 CPU에 알리는 방식이다.

CPU가 장치의 상태를 계속 확인할 필요가 없으므로, 장치가 준비되는 동안 CPU는 다른 작업을 수행할 수 있다.
장치에서 인터럽트가 발생하면 CPU는 현재 실행 중인 작업을 잠시 중단하고 인터럽트 서비스 루틴(ISR)​을 실행하여 해당 I/O 요청을 처리한다.

### 직접 메모리 접근(Direct Memory Access, DMA)
**DMA**는 입출력 장치가 CPU의 개입 없이 메모리와 직접 데이터를 주고받을 수 있도록 하는 방식이다.

CPU가 입출력 장치의 데이터를 하나씩 직접 메모리로 옮기는 대신, DMA 컨트롤러가 데이터 전송을 담당한다.

CPU는 DMA 컨트롤러에 메모리 블록의 시작 주소, 전송할 데이터의 크기, 입출력 장치 등의 정보를 설정하고 전송을 요청한다. 이후 DMA 컨트롤러가 장치와 메모리 사이에서 데이터를 전송하며, 전송이 완료되면 CPU에 인터럽트를 발생시켜 완료 사실을 알린다.

CPU는 데이터 전송을 DMA 컨트롤러에 맡기고 다른 작업을 수행할 수 있기 때문에, CPU의 I/O 처리 부담을 줄일 수 있다.
