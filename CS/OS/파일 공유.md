# 파일 공유
**파일 공유**는 다수의 사용자나 프로세스가 동일한 파일에 접근할 수 있도록 허용하여 자원 관리 효율을 높인다. 

## 다수의 사용자 환경에서의 고려 사항
- **접근 권한**(Access Rights): 파일 소유자는 다른 사용자에게 부여할 접근 권한을 부여하거나 제한할 수 있어야 한다.
- **동시 접근**(Concurrent Access): 여러 사용자가 동시에 파일을 수정할 때 데이터 일관성을 위한 동기화 메커니즘이 필요하다.

## 링크(Link)
파일 시스템에서는 동일한 파일을 여러 경로에서 참조할 수 있도록 **링크**를 제공한다.

### 하드 링크(Hard Link)
**하드 링크**는 동일한 파일에 대한 여러 디렉토리 항목을 생성하는 방식이다.
- 동일한 inode를 참조한다.
- 파일의 실제 데이터는 공유된다.
- 하나의 경로를 삭제해도 다른 하드 링크가 존재하면 파일 데이터는 유지된다.
- 서로 다른 파일 시스템 간에는 하드 링크를 생성할 수 없다.

### 심볼릭 링크(Symbolic Link), 소프트 링크(Soft Link)
**심볼릭 링크**는 다른 파일이나 디렉토리의 경로를 저장하는 별도의 파일이다.
- 대상 파일의 경로를 참조한다.
- 대상 파일과 다른 inode를 가진다.
- 대상 파일이 삭제되거나 이동되면 링크가 유효하지 않을 수 있다.
- 다른 파일 시스템의 파일도 참조할 수 있다.

## NFS (Network File System)
**NFS**는 네트워크를 통해 원격 컴퓨터의 파일시스템에 접근할 수 있도록 하는 클라이언트-서버 기반 파일 공유 프로토콜이다.

- **서버(Server):** 공유할 파일이 저장되어 있으며, 클라이언트의 파일 접근 요청을 처리한다.
- **클라이언트(Client):** 서버의 파일시스템을 자신의 디렉토리에 마운트하여 사용한다.
