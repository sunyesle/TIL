# 파일 개념
파일은 OS가 관리하는 논리적 저장 단위로, 비휘발성 저장 장치에 정보를 저장하기 위한 수단이다.

## 파일 속성
파일을 식별하고 관리하기 위해 OS가 유지하는 메타데이터이다.
| 속성 | 설명 |
|---|---|
| **이름(Name)** | 사용자가 읽을 수 있는 파일 이름이다. |
| **식별자(Identifier)** | 파일 시스템 내에서 파일을 유일하게 식별하는 값이다. |
| **유형(Type)** | 파일의 종류를 나타낸다. |
| **위치(Location)** | 파일이 디스크 상에 저장된 위치이다. |
| **크기(Size)** | 현재 파일의 크기(바이트, 블록)이다. |
| **보호(Protection)** | 파일에 대한 접근 권한(읽기/쓰기/실행)이다. |
| **시간 및 날짜(Time, Date)** | 생성, 수정, 접근 등의 시간 정보를 나타낸다. |

## 파일 연산
OS가 제공하는 파일 조작 시스템콜이다.

- **생성**(Create): 파일 시스템 내에 공간을 확보하고, 필요한 메타데이터 및 디렉터리 엔트리를 생성한다.
- **쓰기**(Write): 파일의 특정 위치에 데이터를 기록하고 쓰기 포인터를 갱신한다.
- **읽기**(Read): 파일의 특정 위치에서 데이터를 읽고 읽기 포인터를 갱신한다.
- **위치변경/탐색**(Reposition/Seek): I/O 작업 포인터 위치를 파일 내의 특정 바이트 위치로 이동시킨다.
- **삭제**(Delete): 파일을 디렉터리에서 제거하고, 파일이 차지하고 있던 디스크 저장 공간을 시스템에 반환한다.
- **잘라내기/크기 조정**(Truncate): 파일의 내용은 유지한 채 특정 길이까지만 남기고 나머지 데이터를 버려 파일 크기를 줄입니다.
- **열기**(Open): 파일 연산을 수행하기 전, 시스템 테이블에 해당 파일의 정보를 올리고 작업 준비를 한다.
- **닫기**(Close): 파일 작업이 끝난 후, 시스템이 유지하던 파일 관련 자원과 버퍼를 반환하고 마무리한다.

## 파일 유형
Windows(및 일부 다른 시스템)는 파일의 유형을 나타내기 위해 파일 확장자를 사용한다. (ex: `.exe`, `.txt`, `.pdf`)

## 파일 구조
파일은 내부 구조를 가질 수 있으며, 그 구조를 OS가 인식하고 처리할 수도 있고 응용 프로그램이 자체적으로 관리할 수도 있다.

OS가 특정 파일 구조를 지원하는 경우 해당 파일 형식을 OS가 이해하고 처리해야 하므로, 지원하는 파일 형식이 많아질수록 OS의 크기와 복잡성이 증가한다.

Unix/Linux는 일반적으로 파일을 **연속적인 바이트 스트림**으로 취급하며, 파일의 구조와 해석은 응용 프로그램이 담당한다. 단, 실행 가능한 바이너리 프로그램은 실행을 위해 OS가 해당 형식을 어느 정도 이해해야 한다.

## 파일의 내부 구조
파일 시스템 관점에서 파일은 하나 이상의 **논리적 단위**(Logical Unit)로 구성되며, 디스크의 **물리적 블록**(Physical Block)에 저장된다.

하나의 물리적 블록에 들어가는 논리적 단위의 개수를 **패킹**(Packing)이라고 한다.

논리적 단위가 물리적 블록을 정확하게 채우지 못하면 블록의 일부 공간이 사용되지 않고 남아 **내부 단편화**(Internal Fragmentation)가 발생할 수 있다.
