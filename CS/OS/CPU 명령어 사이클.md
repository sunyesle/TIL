# CPU 명령어 사이클
**CPU 명령어 사이클**은 CPU가 메모리로부터 명령어를 꺼내와 실행하기 위한 연속적인 동작 과정이다.

명령어 사이클 동안 CPU에서 사용되는 주요 구성 요소는 다음과 같다.

- **PC**: 다음에 인출할 명령어의 메모리 주소를 저장하는 레지스터
- **MAR**: 메모리에 접근할 주소를 저장하는 레지스터
- **MBR**: 메모리에서 읽어온 명령어나 데이터를 임시 저장하거나, 메모리에 기록할 데이터를 보관하는 레지스터
- **IR**: 메모리에서 인출한 현재 실행할 명령어를 임시 저장하는 레지스터
- **CU**: 명령어 인출, 해독, 실행을 위한 제어신호를 타이밍에 맞춰 발생시키는 장치
- **ALU**: 산술 연산과 논리 연산을 수행하는 장치

## 명령어 기본 사이클
CPU의 명령어 사이클은 일반적으로 다음과 같은 단계로 구성된다.

- **Fetch**: 명령어 인출
- **Decode**: 명령어 해독
- **Indirect**: 간접주소인 경우 유효주소 획득
- **Execute**: 명령어 실행
- **Interrupt**: 인터럽트 처리

## 1. Fetch (명령어 인출)
메모리에서 다음에 실행할 명령어를 가져오는 단계이다.

| 마이크로 연산 | 설명 |
|---|---|
| `MAR ← PC` | 다음 명령어의 주소를 MAR에 저장 |
| `MBR ← M[MAR]` | 메모리에서 명령어 읽기 |
| `IR ← MBR` | 가져온 명령어를 IR에 저장 |
| `PC ← PC + 1` | 다음 명령어 주소로 증가 |

## 2. Decode (명령어 해독)
IR에 저장된 명령어를 해독해서 어떤 연산을 수행할지 판단하는 단계이다.

- **Opcode 해독**: 명령어의 연산 코드(Operation Code)를 확인하여 수행할 연산을 판단한다.
- **Operand 해독**: 오퍼랜드의 위치와 주소지정 방식(직접/간접 등)을 확인한다.

## 3. Indirect (간접 사이클)
간접주소지정 방식인 경우, 실제 데이터가 저장된 메모리 주소인 유효 주소(Effective Address)를 가져오는 단계이다.

간접주소지정 방식은 명령어에 포함된 주소가 실제 데이터의 주소를 가리키는 것이 아니라 유효 주소가 저장된 메모리 위치를 가리키므로 메모리에 추가로 접근하여 유효 주소를 가져와야 한다.

| 마이크로 연산 | 설명 |
|---|---|
| `MAR ← IR(ADDRESS)` | 주소 필드를 MAR에 저장 |
| `MBR ← M[MAR]` | 해당 메모리 주소의 내용 읽기 |
| `IR(ADDRESS) ← MBR` | 읽어온 값을 IR의 주소 필드에 저장 |

## 4. Execute (명령어 실행)
해독한 명령어에 따라 실제 연산을 수행하는 단계이다.

명령어 종류에 따라 마이크로 연산이 달라진다.

### 예시
#### `MOV B, [Y]` (데이터 이동)
메모리 Y번지의 데이터를 B 레지스터로 전송한다.
- `MAR ← Y`
- `MBR ← M[MAR]`
- `B ← MBR`
#### `LOAD Y` (데이터 적재)
메모리 Y번지의 데이터를 누산기(AC)에 저장한다.
- `MAR ← IR(ADDRESS)`
- `MBR ← M[MAR]`
- `AC ← MBR`
#### `ADD Y` (덧셈)
메모리의 특정 주소에 저장된 데이터를 누산기(AC)의 값과 더한 후 결과를 AC에 저장한다. (`AC ← AC + M[Y]`)
- `MAR ← IR(ADDRESS)`
- `MBR ← M[MAR]`
- `AC ← AC + MBR`
#### `STORE Y` (데이터 저장)
누산기(AC)에 저장된 데이터를 메모리의 특정 주소에 저장한다. (`M[Y] ← AC`)
- `MAR ← IR(ADDRESS)`
- `MBR ← AC`
- `M[MAR] ← MBR`
#### `JUMP Y` (분기)
(`PC ← Y`) 프로그램 카운터(PC)에 지정된 주소를 저장하여 다음에 실행할 명령어의 위치를 변경한다.
- `PC ← IR(ADDRESS)`

## 5. Interrupt (인터럽트 사이클)
CPU는 명령어 실행을 완료한 후 인터럽트 요청이 있는지 확인한다.

인터럽트 요청이 존재하면 인터럽트 허용 플래그(Interrupt Enable Flag, IE 또는 IF)를 확인하여 인터럽트를 수락할 수 있는지 판단한다.

인터럽트 요청이 존재하고 인터럽트 처리가 허용된 상태라면, 현재 프로그램의 실행 상태를 저장하고 인터럽트 서비스 루틴(ISR)을 실행한다.

### 인터럽트 종류
#### 내부 인터럽트 (Internal Interrupt)
CPU가 명령어를 실행하는 과정에서 발생하는 예외적인 상황이다. 일반적으로 명령어 실행과 직접적인 관련이 있으며, 인터럽트 허용 플래그에 의해 차단되지 않는다.
- **하드웨어 고장**: 정전, 패리티 비트 오류, 기계 검사 오류 등
- **실행할 수 없는 명령어**: 정의되지 않은 명령어 실행
- **명령어 실행 오류**: 0으로 나누는 경우
- **사용 권한 위반**: 허용되지 않은 메모리 접근 등

#### 외부 인터럽트 (External Interrupt)
CPU 외부의 장치나 하드웨어에서 발생하는 인터럽트 요청이다.
- **타이머 인터럽트**: 타이머 장치에 의해 발생
- **입출력 인터럽트**: 키보드, 디스크 등 입출력 장치에 의해 발생
