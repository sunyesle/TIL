# 가상 메모리(Virtual Memory)
## 가상 메모리란
가상 메모리는 프로그램에게 실제 물리적 메모리(RAM)보다 더 큰 메모리 공간을 사용할 수 있게 해주는 메모리 관리 기술이다.
프로그램은 물리 메모리와 독립적인 가상 주소 공간을 사용하며, 운영체제는 이를 실제 메모리의 다양한 위치에 매핑하여 관리한다.

가상 메모리의 기본 원리는 프로세스가 실행될 때 메모리에 해당 프로세스 전체가 적재되지 않더라도 실행할 수 있다는 점에 있다.

프로그램은 실행 중 특정 시점에 프로그램의 전체 영역이 아닌 일부분만 필요로 하므로, 필요한 부분만 메모리에 적재하고 나머지는 보조기억장치에 보관한다.
이를 통해 보조기억장치의 일부 저장 공간을 메모리처럼 활용할 수 있다.

가상 메모리 시스템의 핵심은 모든 메모리 접근 요청을 가상 주소를 통해 처리한다는 점이다.
이 가상 주소는 페이지 테이블을 통해 실제 물리 주소로 변환된다.

### 도입 배경
- **프로그램 크기의 제약**: 프로세스가 사용하는 주소 공간이 물리 메모리(RAM)와 직접 매핑되었기 때문에, 프로그램의 크기가 사용 가능한 물리 메모리보다 클 수 없다는 제약이 있었다.
- **메모리 활용의 비효율성**: 실행에 당장 필요하지 않은 코드와 데이터까지 메모리를 차지하여 메모리 활용 효율이 낮았다.
- **다중 프로그래밍 효율 저하**: 메모리 제한 때문에 동시에 실행할 수 있는 프로세스의 수가 줄어들어 CPU 이용률과 시스템 처리량이 낮아졌다.

### 장점
- **메모리의 효율적 사용**: 프로그램이 실제로 사용하는 부분만 메모리에 적재하여 시스템의 메모리 사용량을 최적화할 수 있다.
- **프로세스 간 격리**: 각 프로세스가 독립적인 가상 주소 공간을 사용하므로 프로세스 간 메모리를 분리하여 관리할 수 있다. 이를 통해 한 프로세스가 다른 프로세스의 메모리에 직접 접근하는 것을 방지하여 시스템의 안정성과 보안성을 높일 수 있다.
- **대규모 프로그램의 실행**: 프로그램의 전체 메모리 요구량이 물리 메모리의 크기를 초과하더라도 필요한 부분만 메모리에 적재하여 실행할 수 있다.

## 요구 페이징(Demand Paging)
가상 메모리는 처음부터 모든 페이지를 메모리에 올려두지 않고, 필요할 때만 불러오는 방식을 사용한다. 이를 **요구 페이징**이라고 한다.
 
> 미리 프로세스와 관련된 모든 데이터를 메모리에 올려놓고 실행하는 **선행 페이징**(Anticipatory Paging)과 반대 개념이다. 
 
### 페이지 테이블의 역할
페이지 테이블의 유효-무효 비트(Valid-Invalid Bit)로 해당 페이지가 메모리에 올라와있는지 표시한다.

| 비트 상태 | 의미 | 처리 |
|---|---|---|
| **Valid** | 페이지가 현재 메모리에 올라와 있음을 의미한다. | 정상적인 주소 변환을 수행한다. |
| **Invalid** | 페이지가 현재 메모리에 없으며 디스크에 저장되어 있음을 의미한다. | 해당 페이지 접근 시 페이지 부재(Page Fault)가 발생한다. |

### 페이지 부재(Page Fault)
**페이지 부재**는 프로세스가 접근하려는 페이지가 메모리에 적재되어 있지 않을 때 MMU가 발생시키는 예외이다.

MMU는 페이지 테이블의 유효-무효 비트를 확인하여 해당 페이지가 메모리에 적재되어 있는지 검사한다.
만약 메모리에 없다면 페이지 부재가 발생하고, CPU의 제어권이 운영체제 커널의 페이지 부재 처리 루틴(page fault handler)으로 넘어간다.

이후에 커널은 다음과 같이 동작한다.
1. **주소의 유효성을 확인한다.**
   - 프로세스가 참조한 가상 주소가 유효한 주소인지 검사한다. 주소가 유효하지 않다면 해당 프로세스를 종료한다.
2. **페이지가 저장된 위치를 확인한다.**
   - 필요한 페이지가 보조기억장치(backing store)에 존재하는지 확인한다.
3. **프레임을 확보한다.**
   - 페이지를 적재할 수 있는 빈 프레임이 있는지 확인한다. 빈 프레임이 없다면 페이지 교체(Page Replacement) 알고리즘을 사용하여 기존 페이지를 내보내고 프레임을 확보한다.
4. **페이지를 메모리에 적재한다.**
   - 확보한 프레임에 필요한 페이지를 적재하기 위해 디스크 I/O를 수행한다. I/O가 완료될 때까지 해당 프로세스는 대기 상태가 될 수 있다.
5. **페이지 테이블을 갱신한다.**
   - 페이지가 프레임에 적재되면 페이지 테이블의 프레임 번호와 유효-무효 비트를 갱신한다.
6. **중단된 명령어를 재실행한다.**
   - 프로세스가 다시 실행되면 페이지 부재가 발생했던 명령어부터 재실행한다. 이제 해당 페이지의 유효-무효 비트가 유효이므로 MMU가 정상적으로 논리 주소를 물리 주소로 변환하고 메모리에 접근할 수 있다.

## 쓰기 시 복사(Copy-on-write, COW)
Copy-on-Write(COW)는 메모리를 복사해야 하는 상황에서 실제로 값을 복사하지 않고 동일한 메모리 영역을 공유하다가, 수정이 발생하는 경우에만 해당 메모리를 복사하는 메모리 관리 기법이다.

프로세스가 메모리를 복사해야 하는 상황에서 처음부터 전체 메모리를 복사하면 불필요한 메모리와 시간이 소모될 수 있다. COW는 이러한 복사를 최대한 늦추어 메모리를 효율적으로 사용할 수 있도록 한다

### 동작 원리
대표적으로 `fork()`를 사용하여 프로세스를 생성할 때 COW가 사용된다.

1. 부모 프로세스가 `fork()`를 호출하면 운영체제는 자식 프로세스를 생성한다.
2. 자식 프로세스는 부모의 페이지 테이블을 복사하여, 동일한 물리 메모리 영역을 공유한다.
3. 공유 중인 메모리 영역은 보호 비트를 읽기 전용으로 설정하여, 부모와 자식 프로세스가 직접 수정하지 못하도록 한다.
4. 부모 또는 자식 프로세스가 공유된 메모리 영역을 수정하려 하면 페이지 부재가 발생한다.
5. 운영체제는 해당 페이지의 내용을 새로운 프레임에 복사한다.
6. 쓰기를 시도한 프로세스의 페이지 테이블이 새 프레임을 가리키도록 업데이트하고 보호 비트를 읽기/쓰기로 변경한다.
7. 쓰기를 시도한 프로세스의 중단된 명령어를 재실행한다.

## 페이지 교체(Page Replacement)
요구 페이징은 요구되는 페이지만 보조기억장치에서 가져온다.
하지만 프로그램들을 실행함에 따라 요구 페이지도 계속 늘어나게 되고, 그러다 보면 언젠가는 메모리가 가득 차게 될 것이다.

**페이지 교체**는 페이지 부재 발생 시 메모리 공간을 확보하기 위해 현재 메모리에 있는 페이지 중 하나를 선택하여 보조기억장치로 내보내는 과정이다.

페이지 교체 과정은 다음과 같다.

1. 필요한 페이지가 메모리에 없으면 페이지 부재가 발생한다.
2. 운영체제는 메모리에서 교체할 페이지(Victim Page)를 선택한다.
3. 교체할 페이지의 수정 비트(Dirty Bit)를 확인하여 페이지가 수정된 경우 보조기억장치에 변경된 내용을 저장한다.(Write-Back)
4. 선택한 페이지를 프레임에서 제거하고, 필요한 페이지를 해당 프레임에 적재한다.
5. 페이지 테이블을 업데이트한다.
6. 중단된 명령어를 재실행한다.

## 페이지 교체 알고리즘

### FIFO 페이지 교체(First In, First Out)
메모리에 가장 먼저 적재된 페이지를 교체한다.

### 최적 페이지 교체(Optimal Page Replacement, OPT)
앞으로 가장 오랫동안 사용되지 않을 페이지를 교체한다.
이론적으로 가장 적은 페이지 폴트를 발생시키지만, 미래의 메모리 접근을 알아야 하므로 실제 시스템에서는 구현하기 어렵다. 성능 평가의 기준으로 사용된다.

### LRU 페이지 교체(Least Recently Used)
가장 오랫동안 사용되지 않은 페이지를 교체한다.
시간 지역성 원리에 기반하며, OPT에 가까운 성능을 보인다.
정확한 LRU 구현은 모든 메모리 참조를 추적해야 하므로 오버헤드 크며, 일반적으로 하드웨어의 지원이 필요하다.

- **카운터**: 페이지에 접근할 때마다 현재 카운터(논리적 시계) 값을 해당 페이지 테이블 엔트리에 저장한다. 카운터 값이 가장 작은 페이지를 교체한다.
- **스택**: 페이지에 접근할 때마다 해당 페이지를 스택의 맨 위로 이동시킨다. 스택의 맨 아래에 있는 페이지를 교체한다.

### LRU 근사 페이지 교체(LRU Approximation)
정확한 LRU 구현의 과도한 오버헤드를 줄이기 위해, 하드웨어가 제공하는 참조 비트 등을 이용하여 LRU 알고리즘과 근사하게 구현한 페이지 교체 알고리즘들이 존재한다.

#### 참조 비트(Reference Bit)
각 페이지에 참조 비트를 두어 최근에 해당 페이지가 참조되었는지를 기록한다.

페이지가 참조되면 해당 페이지의 참조 비트를 1로 설정하며, 운영체제는 주기적으로 참조 비트를 0으로 초기화하여 이후 페이지가 다시 참조되었는지를 확인할 수 있도록 한다. 참조 비트가 0인 페이지를 우선적으로 교체한다.

#### 부가적 참조 비트 알고리즘
각 페이지마다 일정한 크기의 참조 비트를 두어 최근의 참조 기록을 저장한다.

일정한 주기마다 시프트 연산을 진행하고, 현재 참조 비트를 맨 왼쪽 최상위 비트(MSB)에 복사한다. 참조 비트가 가장 작은 페이지를 교체한다.
```
초기       00000000
참조       10000000
다음 주기  01000000
다음 주기  00100000
```
