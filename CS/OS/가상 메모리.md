# 가상 메모리(Virtual Memory)
## 가상 메모리란
가상 메모리는 프로그램에게 실제 물리적 메모리(RAM)보다 더 큰 메모리 공간을 사용할 수 있게 해주는 메모리 관리 기술이다.
프로그램은 물리 메모리와 독립적인 가상 주소 공간을 사용하며, 운영체제는 이를 실제 메모리의 다양한 위치에 매핑하여 관리한다.

가상 메모리의 기본 원리는 프로세스가 실행될 때 메모리에 해당 프로세스 전체가 적재되지 않더라도 실행할 수 있다는 점에 있다.

프로그램은 실행 중 특정 시점에 프로그램의 전체 영역이 아닌 일부분만 필요로 하므로, 필요한 부분만 메모리에 적재하고 나머지는 보조기억장치에 보관한다.
이를 통해 보조기억장치의 일부 저장 공간을 메모리처럼 활용할 수 있다.

가상 메모리 시스템의 핵심은 모든 메모리 접근 요청을 가상 주소를 통해 처리한다는 점이다.
이 가상 주소는 페이지 테이블을 통해 실제 물리 주소로 변환된다.

### 도입 배경
- **프로그램 크기의 제약**: 프로세스가 사용하는 주소 공간이 물리 메모리(RAM)와 직접 매핑되었기 때문에, 프로그램의 크기가 사용 가능한 물리 메모리보다 클 수 없다는 제약이 있었다.
- **메모리 활용의 비효율성**: 실행에 당장 필요하지 않은 코드와 데이터까지 메모리를 차지하여 메모리 활용 효율이 낮았다.
- **다중 프로그래밍 효율 저하**: 메모리 제한 때문에 동시에 실행할 수 있는 프로세스의 수가 줄어들어 CPU 이용률과 시스템 처리량이 낮아졌다.

### 장점
- **메모리의 효율적 사용**: 프로그램이 실제로 사용하는 부분만 메모리에 적재하여 시스템의 메모리 사용량을 최적화할 수 있다.
- **프로세스 간 격리**: 각 프로세스가 독립적인 가상 주소 공간을 사용하므로 프로세스 간 메모리를 분리하여 관리할 수 있다. 이를 통해 한 프로세스가 다른 프로세스의 메모리에 직접 접근하는 것을 방지하여 시스템의 안정성과 보안성을 높일 수 있다.
- **대규모 프로그램의 실행**: 프로그램의 전체 메모리 요구량이 물리 메모리의 크기를 초과하더라도 필요한 부분만 메모리에 적재하여 실행할 수 있다.

## 요구 페이징(Demand Paging)
가상 메모리는 처음부터 모든 페이지를 메모리에 올려두지 않고, 필요할 때만 불러오는 방식을 사용한다. 이를 **요구 페이징**이라고 한다.
 
> 미리 프로세스와 관련된 모든 데이터를 메모리에 올려놓고 실행하는 **선행 페이징**(Anticipatory Paging)과 반대 개념이다. 
 
### 페이지 테이블의 역할
페이지 테이블의 유효-무효 비트(Valid-Invalid Bit)로 해당 페이지가 메모리에 올라와있는지 표시한다.

| 비트 상태 | 의미 | 처리 |
|---|---|---|
| **Valid** | 페이지가 현재 메모리에 올라와 있음을 의미한다. | 정상적인 주소 변환을 수행한다. |
| **Invalid** | 페이지가 현재 메모리에 없으며 디스크에 저장되어 있음을 의미한다. | 해당 페이지 접근 시 페이지 부재(Page Fault)가 발생한다. |

### 페이지 부재(Page Fault)
**페이지 부재**는 프로세스가 접근하려는 페이지가 메모리에 적재되어 있지 않을 때 MMU가 발생시키는 예외이다.

MMU는 페이지 테이블의 유효-무효 비트를 확인하여 해당 페이지가 메모리에 적재되어 있는지 검사한다.
만약 메모리에 없다면 페이지 부재가 발생하고, CPU의 제어권이 운영체제 커널의 페이지 부재 처리 루틴(page fault handler)으로 넘어간다.

이후에 커널은 다음과 같이 동작한다.
1. **주소의 유효성을 확인한다.**
   - 프로세스가 참조한 가상 주소가 유효한 주소인지 검사한다. 주소가 유효하지 않다면 해당 프로세스를 종료한다.
2. **페이지가 저장된 위치를 확인한다.**
   - 필요한 페이지가 보조기억장치(backing store)에 존재하는지 확인한다.
3. **프레임을 확보한다.**
   - 페이지를 적재할 수 있는 빈 프레임이 있는지 확인한다. 빈 프레임이 없다면 페이지 교체(Page Replacement) 알고리즘을 사용하여 기존 페이지를 내보내고 프레임을 확보한다.
4. **페이지를 메모리에 적재한다.**
   - 확보한 프레임에 필요한 페이지를 적재하기 위해 디스크 I/O를 수행한다. I/O가 완료될 때까지 해당 프로세스는 대기 상태가 될 수 있다.
5. **페이지 테이블을 갱신한다.**
   - 페이지가 프레임에 적재되면 페이지 테이블의 프레임 번호와 유효-무효 비트를 갱신한다.
6. **중단된 명령어를 재실행한다.**
   - 프로세스가 다시 실행되면 페이지 부재가 발생했던 명령어부터 재실행한다. 이제 해당 페이지의 유효-무효 비트가 유효이므로 MMU가 정상적으로 논리 주소를 물리 주소로 변환하고 메모리에 접근할 수 있다.
